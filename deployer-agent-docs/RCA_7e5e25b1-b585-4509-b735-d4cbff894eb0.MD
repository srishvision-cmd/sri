## Interpretation / where the bug most likely is
Because rules are **not stored in Mongo** and `product_category` / cover classification is **derived in code**, the "SAOD rule matches a Package policy" behaviour is a **code-level matching bug**, not a data bug. The likely culprits to inspect in the backend source:
- How a policy's cover type / product category is **derived** from `fields.cover_type` ("Standalone OD") and `fields.product_name` ("Stand-Alone Own Damage … Policy"). If a Package policy (`cover_type` = Package / Comprehensive) is being classified as SAOD, the derivation predicate is too loose (e.g. matching on "Private Car" + insurer while ignoring `cover_type`, or a substring match that treats OD as a subset of Package).
- How the commission rule's `products` set is compared to the derived category. If the SAOD rule's product list is empty or uses a broad/startswith/contains match, it will sweep in Package policies.
- Insurer-string normalization (two different ICICI strings exist) can also widen matches.

This needs the application source, which I cannot see. E1 should locate the rule-matching / product-category derivation function in the backend and verify the SAOD predicate excludes Package cover types. The DB currently has no Package ICICI policy, so a code test fixture (one SAOD + one Package ICICI policy) will be needed to reproduce.
