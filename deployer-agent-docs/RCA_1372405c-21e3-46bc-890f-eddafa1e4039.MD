# RCA — "srishvision.co.in blank white page" after latest deploy

## Verdict
**Not an outage.** The deployment is fully live and healthy. The blank page is a **stale cached `index.html`** in the user's browser (and/or the Cloudflare edge) left over from an earlier deploy, pointing at **old JS/CSS asset hashes that no longer exist** on the freshly-deployed pod → those assets 404 → the app never mounts → white page.

## Deployment facts
- Deployment: `insurance-mis-portal` (`4ad0efe9-49ae-4747-bf80-9db112baf341`)
- Template: `farm_ts_react_mongo_base_image`, `frontend_type: kubernetes` (served from the K8s pod via nginx, Cloudflare proxies the custom domain)
- Active run: `1372405c-21e3-46bc-890f-eddafa1e4039` (redeploy) — **status success, completed 2026-10-11 17:43:31Z**
- Image: `...@sha256:9cc5fe34...`

## Evidence
1. **Origin serves the new build:** `https://insurance-mis-portal.emergent.host/` → 200, index.html references `/assets/index-DWj0W8d_.js` + `/assets/index-4ygxDCWe.css`.
2. **Both new asset hashes resolve:** `/assets/index-DWj0W8d_.js` → 200 (JS bundle), `/assets/index-4ygxDCWe.css` → 200 (Tailwind v4). No 404 on the current hashes.
3. **Backend healthy:** `/health` → 200 `{"status":"ok"}`; uvicorn running; no crash in logs.
4. **Custom domain is actually functioning:** active-run pod logs show live browser traffic via Cloudflare edge IPs (172.69.x / 172.71.x) hitting `/api/policies`, `/api/stats`, `/api/auth/me` — all **200 OK**. The app boots, authenticates and loads data through `srishvision.co.in` for clients that fetched the current HTML.
5. **Domains green:** `srishvision.co.in` + `www.srishvision.co.in` both verified=true, ssl_status=active, linked=true (provider cloudflare).
6. **Setup that produces stale HTML:** 5 redeploys between 13:05 and 17:43 today, each emitting new Vite content hashes. A browser/edge that cached the HTML from an earlier image now requests dead hashes.

## Why it's NOT the recent code changes
The theme/CSS/On-Spot/commission-grid changes are present in the deployed bundle, which the origin serves and which Cloudflare clients execute successfully (200s on authenticated API calls). A theme/CSS change cannot blank the page before React mounts; and if the new bundle crashed on boot it would be blank on `emergent.host` too — it is not. Preview passing `yarn typecheck` and rendering cleanly is consistent with this.

## Not reproduced
I could not fetch `srishvision.co.in` directly or run JS in a real browser, so the user's exact blank screen was not reproduced. The diagnosis rests on origin health + successful live Cloudflare-origin API traffic. Confidence: high.

## Remediation
1. **User — hard refresh / incognito** on `https://srishvision.co.in` (Ctrl/Cmd+Shift+R, or a fresh incognito window). This evicts the stale cached `index.html` and pulls the current one referencing live asset hashes. This should restore the page immediately for the affected session.
2. **If it persists across multiple users/devices** (indicating a stale object at the Cloudflare edge rather than just the local browser): the best-effort edge purge that follows a promote clears on its own shortly after a deploy; to force it, trigger one more redeploy from the Deployment Panel (re-fires the cache purge) or purge the Cloudflare cache for the zone.
3. **To confirm**, the user can open DevTools → Network on the live domain and check for any `GET /assets/index-*.js` returning 404 — those 404s are the stale-hash fingerprint.

No source change is required and no manifest change is required. The live infrastructure is healthy.
