## TL;DR root cause
The GCV policies have **GVW 11,280 kg** and **risk start 2026-10-07**. The only Gourav receivable rule covering the 7,500–12,000 kg / "New Vehicle" band (**rule F**, net 20%) has **`valid_from = 2026-10-08`**. The matching payable rule (**rule G**, net 17%) has **no `valid_from`**.

- The **2 policies** that show ₹5,742 / ₹4,881 are the only two with **risk start = 2026-10-08** (on/after rule F's `valid_from`). receivable = 20% × net 28,710 = **₹5,742**; payable = 17% × 28,710 = **₹4,880.70 ≈ ₹4,881** (not capped, since ≤ receivable).
- The **other TN-RTO policies** have risk start **2026-10-07**, one day before rule F's `valid_from` → **no receivable rule matches**. Payable rule G still matches, but `compute()` caps payable to the receivable ceiling (₹0 when no receivable), so they show **receivable "—", payable ₹0** (note: *"No receivable rule matches — payable held at ₹0"*).
- Policies whose **RTO is an unmapped office name ("Sankari", "Thenkasi") or has no RTO at all (new-vehicle regs "NEWB…")** additionally fail the `rtos:["TN"]` prefix test on BOTH rule F and rule G → **both receivable and payable unmatched → all "—"**.
