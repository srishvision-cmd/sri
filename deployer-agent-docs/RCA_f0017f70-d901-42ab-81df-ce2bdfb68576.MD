# RCA — SBI receivable rules missing from Payables / Rate matrix / Compare & margin

## Problem statement
18 SBI receivable rules (saved via AI grid reader, file SBI.xlsx, note "SBI General / Fazil / Aug 2026") appear in the Receivable tab but NOT in Agent-wise payables, Rate matrix, or Compare & margin. Those three views filter rules to `active=True AND superseded_by=None AND (valid_to empty OR valid_to >= today)`.

## Investigation (read-only, production DB `insurance-mis-portal-app`, collection `commission_rules`)
Query: `{ insurer: /SBI/i, kind: "receivable" }` → **15 documents** (not 18 — see discrepancy below).

Every one of the 15 SBI receivable rules has:
- `active: true`  ✅ (NOT the excluder)
- `superseded_by: null`  ✅ (NOT the excluder)
- `valid_from: "2026-08-01"`
- **`valid_to: "2026-08-30"`  ← the excluder**

## Root cause (confirmed)
The excluding field is **`valid_to`**, not `active`. All 15 SBI receivable rules carry `valid_to = "2026-08-30"`, which is in the past relative to the current server date (≥ 2026-10-14, confirmed by the rules' own `created_at` of 2026-10-14T18:20:33–35Z and deployment last-update 2026-10-14T17:44:13Z — the read-only API cannot read the server wall clock directly, but the latest write timestamps place "today" on/after 2026-10-14).

Therefore the view predicate `valid_to >= today` → `2026-08-30 >= 2026-10-14` → **false**, so all 15 rules are filtered out of Payables, Rate matrix, and Compare & margin. The Receivable tab does not apply the date filter, so they still show there.

The AI grid reader derived `valid_to = 2026-08-30` (end of Aug 2026) from the "Aug 2026" note — producing rules that are born already-expired against the current (Oct 2026) date.

## Corrections to the stated hypothesis
- Hypothesised `valid_to = 2026-08-31`; actual value is **`2026-08-30`** (Aug has 31 days, so even the intended month-end is off by one — reader used 30).
- `active` is **true** for all rules — active is NOT the cause.

## Discrepancy to flag
User expected **18** SBI receivable rules; DB holds **15** (`count` confirmed). 3 rules are either not persisted, saved under a different insurer label, or de-duplicated. Worth confirming with the user.

## Distinct insurer values
- Among **receivable** rules (SBI subset): only `"SBI General"`.
- Among **all** commission_rules: `IndusInd General`, `Liberty General`, `National Insurance`, `SBI General`, `Shriram General`, `TATA AIG`.

## Companies dropdown master list
Not found as a stored master/settings list. `app_state` holds only `live_reset_v1` and an `otp_mailbox` doc — no insurers list. There is no `settings`/`companies` collection. `insurer_portals` contains portal rows (`TATA AIG`, `SBI-Gourav`, `SBI`, `ICICI`, `Shriram`, `National -Fazil`, `National-Gourav`) but that is portal config, not the rules-insurer master. The companies dropdown master is therefore almost certainly code/config-driven, not DB-stored.

## Suggested fixes
1. **User / data (immediate):** edit the 15 SBI receivable rules — clear `valid_to` (empty) or set a future date — so they satisfy the view predicate. Can be done in the UI or via a DB data edit.
2. **Code (E1):** fix the AI grid reader's date derivation so a month-label note ("Aug 2026") does not auto-set a past `valid_to` that instantly expires the rule (and note the off-by-one: Aug end is 31, reader used 30). Alternatively, reconsider whether the three views should hard-exclude past-dated rules for historical/record purposes.
